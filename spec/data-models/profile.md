# Profile Data Model

## Purpose
User identity and preferences. Core entity for matchmaking and chat display.

## Scope
- **In scope:** Schema, fields, constraints, RLS policies
- **Out of scope:** Profile CRUD operations (see [Profile Actions](../api/profile-actions.md))

## Dependencies
- [Glossary](../shared/glossary.md) for domain terms

---

## Schema

### Table: `profiles`

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `id` | UUID | PK, FK to `auth.users(id)` | User ID (from Supabase Auth) |
| `email` | string | NOT NULL, unique | User email (from auth) |
| `first_name` | string | NOT NULL | Display name |
| `last_name` | string | NOT NULL | Last name |
| `full_name` | string | nullable | Computed full name (migration field) |
| `avatar_url` | string | NOT NULL | Avatar image URL |
| `bio` | string | nullable | User bio (free text) |
| `age` | int | nullable | User age |
| `gender` | string | nullable | User gender |
| `interests` | string[] | nullable | Array of interest tags |
| `looking_for` | string | nullable | What user is looking for in matches |
| `sliders` | jsonb | nullable | VibeSliders: social_battery, planning, conversation, thinking, risk (0-100) |
| `identity_chips` | string[] | nullable | Selected identity tags |
| `prompt_answer` | jsonb | nullable | {prompt: string, answer: string} from PromptRoulette |
| `ai_summary` | string | nullable | AI-generated profile summary |

### Indexes
```sql
CREATE INDEX idx_profiles_interests ON profiles USING GIN (interests);
CREATE INDEX idx_profiles_identity_chips ON profiles USING GIN (identity_chips);
```

### RLS Policies
```sql
-- All users can read all profiles (for matchmaking)
CREATE POLICY "Anyone can view profiles"
  ON profiles FOR SELECT
  USING (true);

-- Users can update only their own profile
CREATE POLICY "Users can update own profile"
  ON profiles FOR UPDATE
  USING (auth.uid() = id);
```

## Field Details

### Identity Fields
- **first_name, last_name:** Required for display. Collected during onboarding.
- **full_name:** Optional computed field for backwards compatibility.
- **avatar_url:** Required. Set during profile basics step. Default avatar available.

### Matching Fields
- **interests:** Array of strings (e.g., `["hiking", "cooking", "jazz"]`). Used in matchmaking and AI interjections.
- **looking_for:** Free text describing desired match. Used in matchmaking AI prompt.
- **identity_chips:** Predefined tags (e.g., `["introvert", "night owl"]`). Displayed on match cards.

### Identity Stack Fields
- **sliders:** Five 0-100 sliders for personality dimensions. Schema:
  ```typescript
  {
    social_battery: number    // Introvert (0) ↔ Extrovert (100)
    planning: number          // Spontaneous (0) ↔ Planner (100)
    conversation: number      // Deep (0) ↔ Light (100)
    thinking: number          // Logical (0) ↔ Feeling (100)
    risk: number              // Cautious (0) ↔ Adventurous (100)
  }
  ```

- **prompt_answer:** One question-answer pair from PromptRoulette. Schema:
  ```typescript
  {
    prompt: string    // e.g., "What's your ideal Saturday?"
    answer: string    // User's free-text response
  }
  ```

- **ai_summary:** Generated by AI from all profile fields. Used in matchmaking. Example: "Adventurous hiker who loves cooking and seeks deep conversations."

---

## Business Rules

1. **Required fields:** `id`, `email`, `first_name`, `last_name`, `avatar_url`
2. **Sliders:** All 5 must be present if sliders field is set (no partial)
3. **Interests:** Max 10 interests per user (enforced in UI, not DB)
4. **AI summary:** Generated on profile save. Can be regenerated anytime.
5. **Email:** Immutable (tied to auth.users)

---

## Acceptance Criteria

- [ ] Profile can be created with minimum required fields (first_name, last_name, avatar_url)
- [ ] Interests stored as PostgreSQL array (supports GIN index)
- [ ] Sliders stored as JSONB with 5 required keys (social_battery, planning, conversation, thinking, risk)
- [ ] RLS enforces read-all, write-own policy
- [ ] AI summary generated via Gemini API on profile save
